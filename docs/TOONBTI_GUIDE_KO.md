# 인투니 Toon-BTI 운영 가이드

## 개요

Toon-BTI는 운영자가 정의한 4개의 양자 성향축을 기준으로 사용자의 취향을 계산하고, 같은 최종 유형으로 지정된 공개 작가를 모두 보여주는 기능입니다.

축 이름, 8개 성향 코드·이름·설명, 질문, 답변, 결과 설명과 이미지는 프론트엔드 코드가 아니라 Supabase에서 관리합니다.

## 적용할 마이그레이션

운영 DB에는 아래 파일을 한 번 적용해야 합니다.

`supabase/migrations/202607230013_toonbti_scoring_model.sql`

이 마이그레이션은 기존 라우트맵 테이블을 삭제하지 않고 다음 구조를 추가합니다.

| 테이블 | 역할 |
| --- | --- |
| `toon_tests` | 테스트 제목, 소개, 버전, 공개 상태 |
| `toonbti_axes` | 표시 순서가 있는 4개 성향축과 동점 기본 성향 |
| `toonbti_traits` | 각 축에 속하는 2개 성향 |
| `toonbti_questions` | 질문과 연결 축 |
| `toonbti_question_options` | 답변 문구, 연결 성향, 5점/10점 |
| `toonbti_result_types` | 16개 결과의 이름·설명·이미지·공유 문구 |
| `artist_toonbti_types` | 작가와 최종 결과 유형의 FK 연결 |
| `toonbti_events` | 익명 사용 이벤트 |

원본 테이블은 일반 사용자 역할에서 직접 읽거나 쓸 수 없습니다. 관리자 API와 공개 서버 페이지가 서비스 역할을 통해 필요한 활성 데이터만 반환합니다.

## 관리자 설정 순서

관리자 로그인 후 `툰비티아이 관리` 메뉴를 엽니다.

인투니는 Toon-BTI 테스트 하나만 운영합니다. 별도의 테스트 생성이나 기본 설정 단계는 없습니다.

네 축은 아래 고정 기준을 사용하며 관리자 화면에서 임의로 바꾸지 않습니다.

| 축 | 축의 구분 | 코드 | 성향명 | 설명 |
| --- | --- | --- | --- | --- |
| 1축 | 현실 경험과 상상 세계 | R | 현실형 | 실제 일상, 연애, 직장, 가족, 경험담처럼 현실에서 겪을 법한 이야기가 중심 |
| 1축 | 현실 경험과 상상 세계 | F | 판타지형 | 창작 캐릭터, 의인화, 독특한 설정과 세계관처럼 현실 밖의 상상력이 중심 |
| 2축 | 가벼운 재미와 깊은 몰입 | L | 유쾌형 | 웃음, 개그, 병맛, 반전처럼 재미있고 가볍게 즐기는 감정이 중심 |
| 2축 | 가벼운 재미와 깊은 몰입 | D | 몰입형 | 공감, 감동, 위로, 긴장, 감정선처럼 작품에 깊게 빠져드는 경험이 중심 |
| 3축 | 핵심 포인트와 이야기 흐름 | P | 포인트형 | 공감·개그·정보 등 한 가지 핵심 포인트를 빠르고 명확하게 전달 |
| 3축 | 핵심 포인트와 이야기 흐름 | S | 스토리형 | 사건의 시작·전개·결말과 이야기의 흐름이 중심 |
| 4축 | 순한 표현과 강한 표현 | M | 순한맛형 | 편안하고 귀엽거나 잔잔하며, 갈등과 표현의 강도가 비교적 낮음 |
| 4축 | 순한 표현과 강한 표현 | H | 매운맛형 | 강한 사건, 갈등, 자극적인 소재, 거친 표현이나 반전의 강도가 높음 |

1. `축 설정`에서 기본 틀을 만든 뒤 축 4개와 각 축의 성향 2개를 수정합니다.
2. 성향 코드는 테스트 전체에서 겹치지 않는 영문 대문자 또는 숫자 한 글자로 설정합니다.
3. 각 성향에는 공개 결과에 표시할 한글 이름과 설명을 입력합니다.
4. 축마다 동점 시 사용할 기본 성향을 지정합니다.
5. `질문·답변`에서 각 축마다 질문을 정확히 4개 입력합니다. 질문마다 답변 4개를 작성하고, 같은 축의 두 성향 중 하나와 5점 또는 10점을 연결합니다.
6. `결과 유형`에서 누락된 16개 조합을 생성하고 이름, 설명, 이미지와 공유 문구를 채웁니다.
7. `작가 연결` 또는 각 작가의 `기본 정보`에서 네 축을 하나씩 선택하고 저장합니다.
8. 모든 필수 데이터가 준비되면 `검증 후 게시`를 누릅니다.

게시 검증은 활성 축 4개, 축당 활성 성향 2개, 축당 활성 질문 4개, 질문당 활성 답변 4개, 축 내부 참조, 16개 활성 결과를 확인합니다. 검증 실패 시 공개 상태로 전환되지 않습니다.

## 결과 계산

사용자가 고른 답변의 점수를 축별·성향별로 합산합니다.

1. 점수가 높은 성향을 선택합니다.
2. 점수가 같으면 10점 답변을 더 많이 받은 성향을 선택합니다.
3. 10점 답변 수도 같으면 관리자가 지정한 동점 기본 성향을 선택합니다.
4. 기본 성향이 없으면 축 표시 순서상 첫 번째 성향을 선택합니다.

네 축의 승리 코드를 축 표시 순서대로 이어 붙인 값이 최종 코드입니다. 계산은 `lib/domain/toonbti.ts`의 `calculateToonbtiResult` 한 곳에서 수행합니다.

## 작가 연결

작가에게 질문 점수나 문자열 코드를 저장하지 않습니다. `artist_toonbti_types.result_type_id`가 `toonbti_result_types.id`를 참조합니다.

따라서 결과 이름이나 코드를 수정해도 작가 연결 ID는 유지됩니다. 작가 한 명은 테스트 하나에서 결과 유형 하나만 가질 수 있습니다. 미지정 상태도 지원합니다.

공개 결과 페이지는 연결된 작가 중 기존 인투니 공개 조건을 통과한 작가만 반환합니다. 숨김·보관·사이트 비공개 작가는 결과에 나오지 않습니다.

## 사용자 흐름

1. `/toonbti`에서 테스트를 시작합니다.
2. 활성 질문이 표시 순서대로 한 화면에 하나씩 나옵니다.
3. 진행률과 이전 버튼을 사용할 수 있습니다.
4. 진행 상태는 테스트 ID와 버전별로 브라우저 `localStorage`에 저장됩니다.
5. 모든 질문을 완료하면 `/toonbti/result/[resultCode]`로 이동합니다.
6. 결과 페이지에서 설명, 네 성향, 정확히 같은 유형의 공개 작가 전체를 확인합니다.

관리자가 테스트 버전을 올려 저장하면 이전 버전의 브라우저 진행 상태와 섞이지 않습니다.

## 이미지와 공유

관리자 이미지는 기존 업로드 API의 `toonbti/` 경로에 저장합니다.

결과 페이지는 브라우저 Canvas로 1080×1350 PNG 카드를 만듭니다. 카드에는 인투니 표시, 결과 코드·이름, 대표 이미지, 한 줄 설명, 네 성향 이름과 사이트 주소가 들어갑니다. 대표 이미지가 없거나 로딩에 실패해도 텍스트 중심 카드가 생성됩니다.

지원 브라우저에서는 Web Share API를 사용합니다. 지원하지 않는 브라우저에서는 결과 문구와 링크를 클립보드에 복사합니다. 추천 작가의 외부 Instagram 이미지는 공유 카드에 넣지 않습니다.

## 운영 시 주의사항

- 마이그레이션 013 적용 전에는 관리자가 준비 필요 안내를 표시합니다.
- 실제 축 의미와 16개 결과 콘텐츠는 운영자가 입력해야 합니다. 코드에는 예시 성향 의미가 하드코딩되어 있지 않습니다.
- 공개 테스트는 `게시됨 + 활성` 상태이며 16개 결과 검증을 통과한 설정만 노출합니다.
- 질문을 운영 중 제거하려면 삭제보다 비활성화를 사용합니다.
- 이벤트에는 답변 원문을 저장하지 않고 이벤트 종류, 결과 코드, 질문 ID, 작가 ID만 필요에 따라 기록합니다.
